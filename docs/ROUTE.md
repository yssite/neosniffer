# SpaceSniffer 重制：两条技术路线评估与决策

> 本文为历史方案评估。当前仓库的交付范围见 [STATUS.md](STATUS.md)。

> 日期：2026-11-25　结论：**以原生 C++ 为主线交付，.NET 版本保留为对照实现**

## 1. 评估维度

| 维度 | 权重 | 原生 C++ (Win32/GDI) | C# / .NET 10 WinForms |
|---|---|---|---|
| 部署（普通用户零安装） | ★★★★★ | ✅ 单 exe，静态链接，约 1–3 MB，无任何运行库 | ⚠️ 框架依赖版需装 .NET 桌面运行时；自包含单文件约 80–150 MB，启动解压慢 |
| 与原版架构一致性 | ★★★★☆ | ✅ 原生窗口 + 自绘树图 + 消息循环，与原版（Delphi/VCL+Graphics32）同构 | ❌ 托管运行时 + WinForms 控件体系，是另一套架构 |
| 高 DPI 质量 | ★★★★☆ | ✅ PerMonitorV2 + 手动缩放，像素级可控 | ✅ 支持，但 WinForms 的 DPI 兼容层历史包袱多，自绘控件需大量补偿 |
| 深色模式质量 | ★★★★☆ | ✅ 全自绘（菜单/工具栏/标签/滚动条），DWM 标题栏，可做到无白底残留 | ⚠️ WinForms 原生控件无深色模式，只能逐个 owner-draw，仍有边框/滚动条白底 |
| 扫描性能 | ★★★★★ | ✅ 无 GC 抖动，节点池 + 紧凑结构，MFT 直读可达 WizTree 量级 | ✅ 通常够用，但百万节点对象分配带来 GC 压力（需 struct/池化） |
| 体积/内存 | ★★★★☆ | ✅ 内存紧凑（每节点 ~64–80 B） | ⚠️ 每个节点一个托管对象，1M 节点约 150–300 MB |
| 开发风险 | ★★★☆☆ | ⚠️ Win32 样板代码多，布局需手写 | ✅ 开发快，控件现成 |
| 可维护/可扩展 | ★★★★☆ | ✅ 清晰的 C++ 模块 | ✅ 更易读 |
| MCP 集成 | ★★★★☆ | ✅ 单独 console exe，复用 core，无开销 | ✅ 同样可行（需另发一个 exe） |
| 授权/来源 | — | 自写全部代码，无第三方库 | 自写，仅 BCL |

## 2. 关键判断

1. **部署是决定性因素**。用户明确提到「大部分电脑都要装运行库」。原生单 exe 是 SpaceSniffer 这类
   “下载即用工具”的立身之本，这一项直接否决 C# 作为主交付。
2. **架构对齐**。原版是原生 Win32 自绘应用；原生 C++ 能保持同一模型（窗口 + 消息 + 自绘树图 +
   节点树），逆向得到的知识（DFM 布局、树图算法、过滤器/导出 DSL）可以 1:1 落地。
3. **深色 + 高 DPI 的正确性只在自绘路线里可控**。WinForms 的深色是“补丁式”的，滚动条、菜单、
   边框都容易漏白。
4. **C# 版本并非白做**：它已经跑通并验证了全部算法（scanner/MFT/treemap/filter/export/snapshot），
   可以作为 **算法参考实现** 与 **功能对照基线**，也能给只有 .NET 环境的用户一个备用包。

## 3. 决策

- **主线（产品）**：`native/` — Win32 C++20，clang++ 静态编译，单 exe。
- **对照（参考）**：`src/` — 已有 .NET 10 实现，发布为自包含单文件作为备用构建，并作为算法回归基线。
- 两者共享同一份规格：`docs/ANALYSIS.md`（逆向规格）+ `native/BRIEF.md`（实现契约）。

## 5. 验收标准（两版一致）

1. 双击即可运行，无缺失运行库提示。
2. 扫描 `C:\Windows` 这类大目录不崩溃；进度实时；可中途停止。
3. 高 DPI（150%/200%）下无错位、无裁切、字体清晰。
4. 深色模式无白底残留。
5. 过滤器、导出、配置、快照、标签、命令行按逆向规格工作。
6. MCP：`initialize` / `tools/list` / `tools/call` 正常，返回结构化磁盘占用分析。
